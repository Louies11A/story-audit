# 双子代理项目质量闭环实施计划

> **For agentic workers:** 使用 `subagent-driven-development` 执行已授权的审查、修复、复验循环。用户指定两个长期协作角色，维持同一审查代理与修复代理，不再派生其他代理。

**Goal:** 系统审查 story-audit，修复全部经证据确认的问题，并以独立复验和实际测试完成闭环。

**Architecture:** 主代理负责协调、验收、文档和提交；审查代理负责只读审查与独立复验；修复代理负责账本、状态和 API 修复。主代理在审查收口后分担独立的扫描器问题，使用明确文件边界避免冲突。问题编号贯穿报告、修复日志和回归测试。

**Tech Stack:** Python 3.8+ 标准库、pytest、pytest-cov；本机验证解释器为 Python 3.11.15。保持零运行依赖和纯 Python API 约定。

7. 全部确认问题经审查代理复验关闭后，由主代理核对 diff、Git 状态与验证结果，使用中文提交信息提交至功能分支。

## 问题状态机制

`OPEN → CONFIRMED → FIXING → READY_FOR_REVIEW → CLOSED`

- 审查或复现实验确认根因后才进入修复。
- 修复代理提交具体计划与失败回归证据，然后实施最小修复。
- 只有审查代理独立检查需求符合性、代码质量及回归结果后才能关闭问题。
- 复验不通过时重新打开，附失败证据继续循环。
- 重复问题合并编号；证据推翻的问题记录理由，不伪装成已修复。
