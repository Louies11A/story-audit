# 长篇网文深度审查技能 (story-audit) 详细设计规范

> 日期：2026-09-03  
> 状态：Approved（已确认设计）  
> 定位：结合第一性原理、对抗式审查、确定性资源账本与网文短句排版的长篇小说全维度质检系统。

---

## 1. 设计目标与核心理念

长篇网络小说连载往往跨越数十万字至数百万字（数十至数千章）。在长期创作中，作者普遍面临以下核心痛点：
1. **资产失忆**：道具、灵石、技能凭空出现或用过之后无端复活；
2. **因果与事实断裂**：前文重伤后文无故痊愈、战力体系吃书、时空赶路瞬移、跨章断章悬念丢失；
3. **排版视觉窒息**：PC 端大段落导致移动端手机阅读“大黑块”窒息感，AI 翻译腔与书面长难句频出；
4. **作者自嗨与俗套盲区**：沉迷自以为深刻的文青抒情或低智反派拉仇恨，读者却觉得水、毒、俗。

本技能通过**“底层 Python 脚本锁死确定性账本，顶层多 Agent 专家矩阵对抗攻坚，第一性原理把关爽点驱动力，网文短句重塑阅读美感”**，构建起坚实的创作质量护城河。

### 2.2 专家职责明确划分

1. **主审查协调器（Review Coordinator）**：
   - 入口调度，触发 Python 预检；
   - 调度专家子代理或串行协调；
   - 汇总各专家意见，输出标准化 P0~P3 分级报告并归档。
2. **Agent A：资源审计专员（Asset Auditor）**：
   - 结合 Python 账本流水，判定凭空出现的道具/资产；
   - 输出【方案 1：前置补源】与【方案 2：就地修正】双短句方案。
3. **Agent B：时空与事实冲突专员（Continuity & Fact Guard）**：
   - 抓取人物生理/伤势跳跃、战力崩塌、世界规则违背、地理瞬移；
   - 专审上一章末尾与下一章开头的缝合过渡（悬念破局、视点转场）。
4. **Agent C：排版与节奏质检官（Style & Rhythm Coach）**：
   - 审查原书正文的单段长度与行文呼吸感；
   - 对 Agent A、B、D 产出的所有替换文本执行“网文短句化清洗”，确保一句话一行、短促有力。
5. **Agent D：读者第一性与对抗审判官（First-Principles & Adversarial Critic）**：
   - 扮演 15 年书龄的毒舌白金老书虫；
   - 用第一性原理审问“读者为什么追”——本章是否有核心驱动力、期待感和情绪兑付；
   - 撕碎作者自嗨盲区、降智反派、文青谜语人、无脑憋屈等俗套毒点，给出反套路重构方案。

### 2.3 环境自适应与降级机制（Fallback）

- **Multi-Agent 模式（并发）**：在支持 Sub-agent 调用的环境（Claude Code、Codex 等），主协调器并发调度 4 个专家同时分析，审查速度极快。
- **Solo 单会话模式（自动降级）**：在不支持子代理的环境或单进程交互中，主协调器自动退化为分阶段串行思辨（Chain of Thought）：
  `Python预处理 -> 账本核对 -> 事实与跨章 -> 第一性原理与对抗 -> 短句排版清洗 -> 报告输出`，功能完全对齐。

## 3. 资源账本系统与抗膨胀设计

### 3.1 双轨存储与人机协同

- **人类阅读端：`设定/资源账本.md`**：
  - 采用可视化表格与卡片，分门别类，供作者写作时直观翻查当前持有的底牌。
- **机器精确端：`追踪/resource_ledger.json`**：
  - 作为系统的单项真实事实源（SSOT），记录每个资源的精确数量、状态变迁、获取与消耗章位。
- **双向同步逻辑**：
  - Python 脚本日常计算以 JSON 为准，结算后自动重新渲染 Markdown；
  - 作者若手动在 Markdown 中调整道具，通过 `--sync-from-md` 反向增量同步回 JSON，保障人机协同不打架。

### 3.2 七类资产与生命周期状态机

| 资产类型 | 包含范例 | 审计重点 |
| :--- | :--- | :--- |
| **资金资产** | 灵石、铜钱、积分、贡献点、黄金 | 数量结余平衡，严禁支出超收入赤字 |
| **装备道具** | 武器、法宝、防具、储物戒指、钥匙 | 随身携带状态、完好度、损毁与封印 |
| **丹药耗材** | 回复丹、突破丹、毒药、符箓、弹药 | 一次性消耗，严禁已耗尽物品无理由复活 |
| **功法神通** | 心法、武技、异能、血脉被动 | 境界前置限制、冷却时间与反噬代价 |
| **身份权限** | 宗门令、官印、军衔、密令通行证 | 有效期、生效势力范围、剥夺状态 |
| **随行战力** | 契约灵兽、傀儡、护道暗卫 | 伤势状态、召唤限制、空间跨越约束 |
| **全局状态** | 秘境压制、中毒、诅咒、易容伪装 | 持续时限、解除条件与超负荷动作限制 |

**状态机**：
`UNACQUIRED` (未持有) -> `ACQUIRED` (已获取) -> `EQUIPPED` (已在手/佩戴) -> `CONSUMED` (已消耗) / `DAMAGED` (损毁) / `TRANSFERRED` (转让/借出) -> `RESTORED` (修复/解封)。

### 3.3 凭空出装的双方案修复生成机制

当章节中出现账本未收录的资源，Agent A 必须提供两种网文短句风格的修复范例：
- **方案 1【前置补源 / 追溯交代】**：
  - 适用：该道具对当前装逼打脸或破局至关重要，不可删除。
  - 范例：在前一章战利品清点或本章开头以极简短句交代（“昨夜摸尸得来的二阶符，一直藏在袖中”）。
  - 联动：账本对应补录获取记录。
- **方案 2【就地修正 / 等价平替】**：
  - 适用：该道具并非核心，可用已有资源或环境借力化解。
  - 范例：修改当前动作，改用主角已持有的基础武器或功法平替（“顾渊没有掏符，而是反手拔出腰间青钢剑，借石壁火星强袭”）。
  - 联动：账本无需新增道具，杜绝账目通胀。

### 3.4 百万字长篇抗膨胀四大设计

为了防止连载到几百上千章时账本爆炸、Token 耗尽：
1. **分卷封账快照（Snapshot Checkpoint）**：
   - 每卷/大副本结束，运行 `--checkpoint --volume N`；
   - 细碎流水归档入 `追踪/archive/volume_XX_ledger.json`；
   - 只将当期“期末净资产清单”（随身核心道具与灵石结余）作为新卷初始基线，上下文始终维持在 15KB 以内。
2. **冷热资产分层（Hot / Cold Tiering）**：
   - 热资产（随身佩戴、核心功法、常用药）展示在 Markdown 顶层；
   - 冷资产（已消耗药品、损毁装备、过期令牌）自动移入文末折叠区或冷库。
3. **按章动态投影（On-Demand Projection）**：
   - 脚本在审查某章前，先做关键词提取，仅向 Agent 喂入与本章涉及实体相关的历史链条，实现 O(1) 级 Token 消耗。
4. **地图升界置换（Map Ascendancy）**：
   - 换界飞升时，一键将上一界凡俗货币与低阶物品打包入库，开启新层级计量单位。

## 4. 上下文一致性、事实冲突与跨章承接

### 4.1 核心事实审查四大规则

1. **生理与伤势负荷闭环**：
   - 严查断臂、内伤未治疗即狂暴重击；中毒未解药即全力施展轻功。
2. **时空时序与地理因果**：
   - 严查正午两句话后变繁星、千里距离凡马半日瞬移、发作倒计时超期被遗忘。
3. **战力阶梯与世界观规则**：
   - 严查无合理外挂越级秒杀、禁空/禁魔秘境突然违规御剑、禁术无视虚弱副作用连发。
4. **存在性与信息不对称**：
   - 严查已斩首死人无复活暗线作为路人登场、反派密谋主角在无情报源下全知。

### 4.2 跨章承接与断章衔接审计（缝合质检）

每次审查新章时，强制将**“上一章末尾最后 300 字”**与**“新章开头前 300 字”**进行对齐质检：
1. **悬念与危机承接**：严禁“上章命悬一线被刀架脖子，下章开头在茶馆吃包子”；下一章开头前三段内必须直接破局或交代结果。
2. **视点与场景转场**：跨场景或跨视角切换，必须包含明确网文转场短句（如“同一时刻。”、“三千里外，宗门大殿。”），禁止突兀无主语跳跃。
3. **关键对话问答闭环**：上一章末尾抛出的关键质问或惊天秘密，下一章开头角色必须作出正面反应。

## 5. 短句排版审计与网文短句美学

### 5.1 确定性排版硬指标（Python `format_scanner.py`）

| 检查项 | 判定阈值 | 严重度 | 说明与读者影响 |
| :--- | :--- | :--- | :--- |
| **单段臃肿** | 单段连续字数 >= 120 字 | P2 / P3 | 手机端占满半屏，造成视觉窒息与弃读 |
| **长句拖沓** | 句号间逗号 >= 4 个，或分句 >= 45 字无标点 | P2 | 呼吸感窒息，典型书面语病 |
| **对话动作混排** | 台词后紧塞 80 字以上的外貌/环境描写不分行 | P3 | 切碎对话节奏，混淆说话人 |
| **AI 连词堆叠** | 密集出现“然而、与此同时、不可否认的是、值得注意的是” | P3 | 典型翻译腔，破坏网文干脆利落的口语快节奏 |

### 5.2 网文短句黄金法则

1. **一行动作，一句呼吸**：单动词推进，动作拆分，动词前置（“侧身。出刀。断魂。”）。
2. **对话独占成行**：对话前后强制换行，神态动作紧随其后作为短句独立成段。
3. **克制标点与情绪留白**：严禁连用三个以上叹号或问号，多用句号定音。

### 5.3 Agent C 终审清洗管道 (Sanitizer)

所有专家（Agent A/B/D）生成的修改文本，在呈现给作者前，必须经由 Agent C 洗练：
- 单句 > 25 字强制切句；
- 书面语从句强制转为动作直叙；
- 段落连缀强制回车切分成 1~2 行微段落。

## 6. 第一性原理与对抗式审查

### 6.1 第一性原理：读者为什么追？

1. **信息差优势与期待感（Expectation Gap）**：
   - 审查本章主角的欲望（Desire）与阻碍；
   - 是否存在“读者知道底牌，周围人不知道”的信息差溢价；
   - 是否在“压弹簧（蓄力危机）”或“释放弹簧（爽点兑现）”；
   - **红牌判定**：若全章无蓄力、无兑现、平铺直叙，判为 `[P1 驱动力熄火 - 无效叙事/自嗨灌水]`。
2. **情绪报酬确定性（Payoff Assurance）**：
   - 严查“主角付出巨大代价却换来空头支票”或“为了虐而虐的强行憋屈”。

### 6.2 对抗式审查：毒舌老书虫打碎自嗨

由 Agent D 扮演挑剔、刻薄、无耐心的白金读者，专打作者自嗨：
1. **撕碎脸谱化低智反派**：反问反派叫嚣是否低幼？利益诉求何在？提供高智商阴冷博弈替代方案。
2. **斩断文青谜语人**：反问 800 字人生哲理读者是否想跳读？提供以刀剑和行动代替说教的方案。
3. **破除无脑强行憋屈**：反问主角能掀桌子为什么硬忍三章？提供借力打力当场反制的方案。
4. **拒绝换皮复读**：反问本章情节套路是否是上一卷的简单复制。

## 7. P0~P3 分级报告 Schema 与归档目录

### 7.1 四级严重度定义

- **P0 致命断裂**：主线崩溃、死人无伏笔复活、战力体系吃书。**阻断发布，必须重写。**
- **P1 严重失误**：凭空出装、伤势无故痊愈、跨章危机丢失、驱动力熄火、严重俗套毒点。**本轮必修。**
- **P2 局部瑕疵**：>= 120 字臃肿大黑段、长句连缀、视角切换突兀、轻微时空时序漂移。**建议顺手修。**
- **P3 润色建议**：AI 味连词、对白微调、断章钩子打磨。**自主选择。**

## 8. CLI 交互契约与自包含技能文件结构

### 8.1 命令行接口

```bash
# 1. 日常单章审查（默认审最新章，自动比对上一章末尾，更新账本）
python scripts/story_audit.py --chapter 31

# 2. 批量多章连审（连载中一次性审一个小高潮区间）
python scripts/story_audit.py --scope 31-35

# 3. 首次全量建账（逆向回溯旧章节，生成初始双轨账本）
python scripts/story_audit.py --init --scope 1-30

# 4. 人工修改账本后反向同步（作者手改 Markdown 后，同步至机器 JSON）
python scripts/story_audit.py --sync-from-md

# 5. 分卷封账结转（达到百章规模时，生成期末快照，旧流水归档入冷库）
python scripts/story_audit.py --checkpoint --volume 1
```
