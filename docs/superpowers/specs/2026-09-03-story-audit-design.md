# 长篇网文深度审查技能 (story-audit) 详细设计规范

> 日期：2026-09-03  
> 状态：Approved & Reinforced（已审查并深度加固）  
> 定位：结合第一性原理、对抗式审查、确定性双轨资源账本与网文短句排版的军工级小说全维度质检系统。

---

## 1. 设计目标与核心理念

长篇网络小说连载跨越数十万字至数百万字（数十至数千章）。在长期创作中，作者普遍面临以下核心痛点：
1. **资产失忆**：道具、灵石、技能凭空出现或用过之后无端复活，多角色借还混乱，伏笔被误杀；
2. **因果与事实断裂**：前文重伤后文无故痊愈、战力体系吃书、时空赶路瞬移、跨章断章悬念丢失；
3. **排版视觉窒息**：PC 端大段落导致移动端手机阅读“大黑块”窒息感，AI 翻译腔与书面长难句频出；
4. **作者自嗨与俗套盲区**：沉迷自以为深刻的文青抒情或低智反派拉仇恨，读者却觉得水、毒、俗；
5. **工程落地脆弱**：编码报错崩溃（GBK/UTF-8-SIG）、特殊章节识别失败、系统流面板被误判为排版缺陷。

本技能通过**“底层零依赖安全引擎锁死确定性账本，顶层多 Agent 专家矩阵对抗攻坚，第一性原理把关爽点驱动力，网文短句重塑阅读美感”**，构建起坚实的创作质量护城河。

### 2.2 专家职责明确划分

1. **主审查协调器（Review Coordinator）**：
   - 统一入口调度，驱动底层 Python 引擎预处理；
   - 调度专家子代理或串行思辨；
   - 汇总各专家意见，输出标准化 P0~P3 分级报告并归档；
   - 管理原子备份与安全回写执行契约。
2. **Agent A：资源审计专员（Asset Auditor）**：
   - 结合 Python 账本流水，严格核对多实体（主角、战宠、队友）资产变迁；
   - 识别暗线伏笔与暂借流转，避免误杀作者埋线；
   - 对凭空出现资产输出【方案 1：前置补源】与【方案 2：就地修正】双短句范例。
3. **Agent B：时空与事实冲突专员（Continuity & Fact Guard）**：
   - 抓取人物生理/伤势跳跃、战力崩塌、世界规则违背、地理瞬移；
   - 专审上一章末尾与下一章开头的接缝过渡（危机悬念、多线 POV 切换）；
   - 执行叙事视界隔离，防范回忆闪回、心魔幻境造成的事实时序误判。
4. **Agent C：排版与节奏质检官（Style & Rhythm Coach）**：
   - 审查原书正文的单段长度与行文呼吸感（白名单豁免属性面板与古诗口诀）；
   - 对 Agent A、B、D 产出的所有替换文本执行“网文短句化清洗”，确保一句话一行、短促有力。
5. **Agent D：读者第一性与对抗审判官（First-Principles & Adversarial Critic）**：
   - 扮演 15 年书龄的毒舌白金老书虫；
   - 用第一性原理审问“读者为什么追”——量化评估压弹簧蓄力与有效情节位移；
   - 撕碎作者自嗨盲区、降智反派、文青谜语人、无脑憋屈等俗套毒点，给出反套路重构方案。

### 2.3 环境自适应与降级机制（Fallback）

- **Multi-Agent 模式（并发）**：在支持 Sub-agent 调用的环境（Claude Code、Codex 等），主协调器并发调度 4 个专家同时分析，审查速度极快。
- **Solo 单会话模式（自动降级）**：在不支持子代理的环境或单进程交互中，主协调器自动退化为分阶段串行思辨（Chain of Thought）：
  `Python预处理 -> 账本核对 -> 事实与跨章 -> 第一性原理与对抗 -> 短句排版清洗 -> 报告输出`，功能完全对齐。

## 3. 资源账本系统与抗膨胀设计

### 3.1 双轨存储与人机协同

- **人类阅读端：`设定/资源账本.md`**：
  - 采用可视化表格与卡片，分门别类，供作者写作时直观翻查当前持有的底牌。
- **机器精确端：`追踪/resource_ledger.json`**：
  - 作为系统的单项真实事实源（SSOT），记录每个资源的精确数量、状态变迁、获取与消耗章位。
- **双向同步逻辑**：
  - Python 脚本日常计算以 JSON 为准，结算后自动重新渲染 Markdown；
  - 作者若手动在 Markdown 中调整道具，通过 `--sync-from-md` 反向增量同步回 JSON，保障人机协同不打架。

### 3.2 七类资产与扩展状态机

| 资产类型 | 包含范例 | 审计重点 |
| :--- | :--- | :--- |
| **资金资产** | 灵石、铜钱、积分、贡献点、黄金 | 数量结余平衡，严禁支出超收入赤字 |
| **装备道具** | 武器、法宝、防具、储物戒指、钥匙 | 随身携带状态、完好度、损毁、借出与封印 |
| **丹药耗材** | 回复丹、突破丹、毒药、符箓、弹药 | 一次性消耗，严禁已耗尽物品无理由复活 |
| **功法神通** | 心法、武技、异能、血脉被动 | 境界前置限制、冷却时间与反噬代价 |
| **身份权限** | 宗门令、官印、军衔、密令通行证 | 有效期、生效势力范围、剥夺状态 |
| **随行战力** | 契约灵兽、傀儡、护道暗卫 | 伤势状态、召唤限制、灵宠自主消耗 |
| **全局状态** | 秘境压制、中毒、诅咒、易容伪装 | 持续时限、解除条件与超负荷动作限制 |

**扩展状态机**：
`UNACQUIRED` (未持有) -> `ACQUIRED` (已获取) -> `EQUIPPED` (已在手/佩戴) -> `CONSUMED` (已消耗) / `DAMAGED` (损毁) / `TRANSFERRED` (永久转让) / `LENT_OUT` (暂借借出) -> `RECLAIMED` (收回) / `RESTORED` (修复/解封)。

### 3.3 伏笔缓冲机制与多实体资产流转协议 (Foreshadowing & Multi-Entity)

1. **暗线伏笔缓冲池 (Foreshadowing Stash)**：
   - 针对作者故意隐去来历的底牌道具，允许在正文中通过隐形注释标记：
     `<!-- audit:stash name="九龙玉玺" origin="第10章秘境暗格" status="CONCEALED" -->`
   - Agent A 扫描正文遇到未收录核心道具时，优先扫描上下文是否存在隐形伏笔标记或前置暗扣动作（如“怀中硬物”、“暗自捏诀”）。
   - 若符合伏笔特征，报告降级为 `[P2 待认领伏笔提示]`，并附带一键录入伏笔指令，严禁直接粗暴判为凭空出装破坏剧情高潮。

2. **多主体资产所有权与暂借 (Multi-Entity Ownership)**：
   - 账本实体对象扩展数据结构：
     ```json
     {
       "id": "item_frost_sword",
       "name": "霜华剑",
       "owner": "主角",
       "current_holder": "师妹陆雪",
       "status": "LENT_OUT",
       "lend_meta": {
         "lent_in_chapter": 30,
         "purpose": "防身阻敌",
         "expected_return": 33
       },
       "constraints": {
         "durability": { "current_charges": 3, "max_charges": 3 },
         "time_limit": "3天",
         "binding_env": "极寒秘境"
       }
     }
     ```
   - 状态机支持 `LENT_OUT` (借出) 与 `RECLAIMED` (收回)。当持有人在战斗中使用借来道具时，合规通过，不视为借入者凭空出装，亦不视为借出者道具复活。

### 3.4 凭空出装的双方案修复生成机制

当章节中出现账本未收录的资源，Agent A 必须提供两种网文短句风格的修复范例：
- **方案 1【前置补源 / 追溯交代】**：
  - 适用：该道具对当前装逼打脸或破局至关重要，不可删除。
  - 范例：在前一章战利品清点或本章开头以极简短句交代（“昨夜摸尸得来的二阶符，一直藏在袖中”）。
  - 联动：账本对应补录获取记录。
- **方案 2【就地修正 / 等价平替】**：
  - 适用：该道具并非核心，可用已有资源或环境借力化解。
  - 范例：修改当前动作，改用主角已持有的基础武器或功法平替（“顾渊没有掏符，而是反手拔出腰间青钢剑，借石壁火星强袭”）。
  - 联动：账本无需新增道具，杜绝账目通胀。

### 3.5 百万字长篇抗膨胀四大设计

为了防止连载到几百上千章时账本爆炸、Token 耗尽：
1. **分卷封账快照（Snapshot Checkpoint）**：
   - 每卷/大副本结束，运行 `--checkpoint --volume N`；
   - 细碎流水归档入 `追踪/archive/volume_XX_ledger.json`；
   - 只将当期“期末净资产清单”（随身核心道具与灵石结余）作为新卷初始基线，上下文始终维持在 15KB 以内。
2. **冷热资产分层（Hot / Cold Tiering）**：
   - 热资产（随身佩戴、核心功法、常用药）展示在 Markdown 顶层；
   - 冷资产（已消耗药品、损毁装备、过期令牌）自动移入文末折叠区或冷库。
3. **按章动态投影（On-Demand Projection）**：
   - 脚本在审查某章前，先做关键词提取，仅向 Agent 喂入与本章涉及实体相关的历史链条，实现 O(1) 级 Token 消耗。
4. **地图升界置换（Map Ascendancy）**：
   - 换界飞升时，一键将上一界凡俗货币与低阶物品打包入库，开启新层级计量单位。

## 4. 上下文一致性、事实冲突与叙事视界隔离

### 4.1 核心事实审查四大规则

1. **生理与伤势负荷闭环**：
   - 严查断臂、内伤未治疗即狂暴重击；中毒未解药即全力施展轻功。
2. **时空时序与地理因果**：
   - 严查正午两句话后变繁星、千里距离凡马半日瞬移、发作倒计时超期被遗忘。
3. **战力阶梯与世界观规则**：
   - 严查无合理外挂越级秒杀、禁空/禁魔秘境突然违规御剑、禁术无视虚弱副作用连发。
   - **越级反杀确定性基线**：同境界小层次越级需交代功法品质优势；跨大境界（如练气杀筑基）必须具备“绝对规则级外力”（大能神念、天道残卷、极品法宝自爆），否则判 P0 战力崩溃。
4. **存在性与信息不对称**：
   - 严查已斩首死人无复活暗线作为路人登场、反派密谋主角在无情报源下全知。

### 4.2 叙事视界隔离与 POV 切换豁免规则

1. **闪回回忆与心魔幻境 (Flashback & Illusion Isolation)**：
   - 当正文出现回忆/幻境标记（如“五年前那一战……”、“恍惚间”、“陷入心魔幻境”）时，Agent B 启动时空隔离栈；
   - 隔离期间，角色生理状态（如断臂完好）、地理坐标（身处旧址）不与当前主线物理状态比对；
   - 闪回结束后，强制检查跳出标记（“收回思绪”、“深吸一口气，回到现实”），确保主线生理状态与时空无缝复位。

2. **跨章 POV 视点漂移与侧面烘托识别**：
   - 每次审查新章时，将“上一章末尾 300 字”与“新章开头 300 字”对齐质检。
   - **侧面烘托豁免**：若新章开头声明了视点转场（如“与此同时，三千里外皇城”、“同一时刻，妖皇宫中”），豁免“前三段强制破局”要求；
   - 转为审查“该视角是否在反哺主线事件或提供信息差”；若该视点连续超 800 字与主线事件毫无关联，判为 `[P2 视点脱轨 - 节奏拖沓]`。
   - 若无转场标记，严格审查上一章悬念是否在开头前三段内得到正面破局与交接。

## 5. 短句排版审计与网文短句美学

### 5.1 确定性排版硬指标（Python `format_scanner.py`）

| 检查项 | 判定阈值 | 严重度 | 说明与读者影响 |
| :--- | :--- | :--- | :--- |
| **单段臃肿** | 单段连续字数 >= 120 字 | P2 / P3 | 手机端占满半屏，造成视觉窒息与弃读 |
| **长句拖沓** | 句号间逗号 >= 4 个，或分句 >= 45 字无标点 | P2 | 呼吸感窒息，典型书面语病 |
| **对话动作混排** | 台词后紧塞 80 字以上的外貌/环境描写不分行 | P3 | 切碎对话节奏，混淆说话人 |
| **AI 连词堆叠** | 密集出现“然而、与此同时、不可否认的是、值得注意的是” | P3 | 典型翻译腔，破坏网文干脆利落的口语快节奏 |

### 5.2 文本特殊区块排版白名单过滤 (Masking Filter)

在 `format_scanner.py` 进行字数与逗号扫描前，底层执行白名单清洗掩码，避免严重误报：
1. **系统流属性面板**：匹配以 `【`、`[`、`|` 开头且含有“力量/敏捷/境界/寿元/技能点”等关键字的连续行，全块豁免长段检测；
2. **功法口诀与古诗词**：匹配四六言排比句式或带有居中排版意图的古体短文，豁免逗号密集度检测；
3. **书信、公文与系统公告**：以 Markdown 引用块（`>`）或连续引号包裹的宣读性公文，豁免大黑段检测；
4. **高潮情绪长短句交错**：若单段虽长，但连续包含 3 个以上感叹号或强动作动词的激昂独白，从 P2 降级为 P3 提示。

### 5.3 网文短句黄金法则与终审清洗 (Sanitizer)

1. **一行动作，一句呼吸**：单动词推进，动作拆分，动词前置（“侧身。出刀。断魂。”）。
2. **对话独占成行**：对话前后强制换行，神态动作紧随其后作为短句独立成段。
3. **克制标点与情绪留白**：严禁连用三个以上叹号或问号，多用句号定音。
4. **Agent C 终审清洗**：所有专家（Agent A/B/D）生成的修改文本，在呈现给作者前，必须经由 Agent C 洗练：单句 > 25 字强制切句，书面语从句强制转为动作直叙。

## 6. 第一性原理与对抗式审查

### 6.1 第一性原理：读者为什么追？（量化判定卡尺）

审查每一章是否提供了不可替代的情绪驱动力，严厉杜绝把“精妙铺垫”误判为“水文”，把“恶意拖沓”误放行：

| 维度指标 | 【有效蓄力铺垫（压弹簧）】（放行/激励） | 【恶意自嗨灌水】（判 P1 驱动力熄火） |
| :--- | :--- | :--- |
| **危机与代价** | 敌对压迫或生存倒计时在逐步逼近，主角行动受限 | 危机停滞，主角无紧迫感，与路人谈笑风生或水字数 |
| **信息差收益** | 揭示了反派底牌、秘境规则或新机缘线索（情节有位移） | 纯粹复读已知世界观、重复感慨世道艰险（信息增量为 0） |
| **情绪钩子** | 明确给出下一次兑现的爆发倒计时（“三日后的决斗”） | 无明确时间节点，看不出当前行为对后文有何推进 |
| **旁观者反应** | 围观群体的嘲讽直接刺激矛盾升级，推动主角立下誓约 | 超过 3 段同质化的“众人倒吸一口凉气/恐怖如斯”惊叹 |

### 6.2 对抗式审查：毒舌老书虫打碎自嗨

由 Agent D 扮演挑剔、刻薄、无耐心的白金读者，专打作者自嗨：
1. **撕碎脸谱化低智反派**：反问反派叫嚣是否低幼？利益诉求何在？提供高智商阴冷博弈替代方案。
2. **斩断文青谜语人**：反问 800 字人生哲理读者是否想跳读？提供以刀剑和行动代替说教的方案。
3. **破除无脑强行憋屈**：反问主角能掀桌子为什么硬忍三章？提供借力打力当场反制的方案。
4. **拒绝换皮复读**：反问本章情节套路是否是上一卷的简单复制。

## 8. CLI 交互契约、退出码与安全回写

### 8.1 命令行接口

```bash
# 1. 日常单章审查（默认审最新章，自动比对上一章末尾，更新账本）
python scripts/story_audit.py --chapter 31

# 2. 批量多章连审（连载中一次性审一个小高潮区间）
python scripts/story_audit.py --scope 31-35

# 3. 首次全量建账（逆向回溯旧章节，生成初始双轨账本）
python scripts/story_audit.py --init --scope 1-30

# 4. 人工修改账本后反向同步（作者手改 Markdown 后，同步至机器 JSON）
python scripts/story_audit.py --sync-from-md

# 5. 分卷封账结转（达到百章规模时，生成期末快照，旧流水归档入冷库）
python scripts/story_audit.py --checkpoint --volume 1

# 6. 安全采纳回写（将方案1或方案2安全打入正文，带原子备份）
python scripts/story_audit.py --chapter 31 --apply-fix 1
```

### 8.2 CLI 退出状态码 (Exit Codes)

| 退出码 | 含义 | 对应场景 | CI/Pre-commit 行为 |
| :--- | :--- | :--- | :--- |
| **0** | Success (绿灯) | 审查全通，或仅存在 P2/P3 建议项 | 正常放行，允许 Commit/发布 |
| **1** | Warning (黄灯) | 存在 P1 级严重失误（账本缺失、因果断裂） | 输出警告；若带 `--strict` 则中断 |
| **2** | Blocked (红灯) | 存在 P0 级致命断裂（主线崩坏、死人复活） | **强制中断并阻断流程** |
| **3** | Error (错误) | 物理文件找不到、编码异常、账本 JSON 损坏 | 打印排查指南并退出 |

### 8.3 正文修改安全回写契约 (Safe Write-Back Contract)

当作者采纳修复方案并使用 `--apply-fix` 回写时，执行三道严密安全防护：
1. **原子备份 (Atomic Backup)**：
   - 修改前自动将原始文件镜像至 `reports/.bak/{章节名}_{时间戳}.bak`，保证可一键秒级还原；
2. **三行锚点对齐 (Context Anchor Alignment)**：
   - 严禁根据易漂移的绝对行号直接覆盖；
   - 替换算法必须匹配待替换位置的 `前一句 + 目标句 + 后一句`，三重锚点唯一验证后方可落盘；
3. **编码与换行原样保持 (Encoding & EOL Preservation)**：
   - 读取时识别的源文件编码（UTF-8-SIG 或 GB18030）与换行符风格（CRLF/LF），在回写时 100% 保持原样，杜绝乱码与换行破坏。

### 8.4 零外部依赖与鲁棒性工程约定

1. **零第三方依赖承诺**：底层 Python 脚本（`story_audit.py`, `ledger_engine.py`, `format_scanner.py`, `chapter_linker.py`, `safe_io.py`）严格使用 Python 3.8+ 标准库实现（仅依赖 `json`, `re`, `pathlib`, `argparse`, `difflib`, `typing`），无需任何 `pip install`。
2. **统一安全 I/O 流**：自动探测编码顺序 `utf-8-sig` -> `utf-8` -> `gb18030`，在内存中将 `\r\n` 归整为 `\n`。
3. **智能章节匹配器 (ChapterResolver)**：支持阿拉伯数字与大写汉字（`第031章`、`第31章`、`第三十一章`、`031_破局`、`第31章（上）`、`序章`），严禁因命名不规则导致匹配失效。
